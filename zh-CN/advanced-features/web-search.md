# 联网搜索

联网搜索让一个普通的对话请求在模型回答之前先搜索网络。网关执行搜索，把结果作为参考资料注入会话，模型据此给出有时效性的回答——无需函数调用、无需工具调用循环、无需升级 SDK。它兼容**所有模型**，包括众多自身不带搜索能力的模型。

联网搜索适合答案必须反映**当下事实**的场景——新闻、价格、发行说明、频繁变动的文档。若需要稳定的内部参考资料，请使用[知识库]({% link zh-CN/advanced-features/knowledge-base.md %})；两者可在同一请求上组合使用。

---

## 工作原理

联网搜索工具以三种**搜索模式**之一运行：

| 模式 | 行为 |
|---|---|
| **厂商支持时用厂商搜索，否则用 Routero**（*默认*） | 具备内建厂商搜索的模型使用厂商搜索，其余模型回退到 Routero 搜索引擎。这是唯一能在混合模型阵容下都表现正确的模式——你无需追踪哪个模型支持什么。 |
| **只用厂商搜索** | 只使用模型厂商自己的搜索；不支持的模型不搜索——请求本身照常成功。 |
| **一律使用 Routero 搜索** | 每个请求都使用 Routero 搜索引擎，即使模型自带搜索。适合要统一行为、或不希望查询词到达模型厂商的租户。 |

**厂商侧路径**（前两种模式）开启厂商内建的搜索——与你逐个厂商配置的原生能力相同——由工具的[搜索深度与域名过滤](#搜索深度与域名过滤)驱动。引用（citation）以厂商自己的格式返回。

**Routero 引擎路径**兼容任何模型。每个请求会：

1. 网关用会话中最近几轮用户消息构造查询。
2. 用平台的搜索引擎执行查询，取前几条结果（最多五条）。
3. 结果被注入到最后一条用户消息中，作为一个明确标注的**参考资料而非指令**块——每条结果是一个带摘要的 Markdown 链接——与知识库使用相同的防提示词注入框架。
4. 如果搜索没有返回结果，请求照常进行。

联网搜索**失败开放（fail-open）**：搜索后端失败或不可用时绝不会中断对话请求——请求会正常通过，只是不带搜索上下文。联网搜索钩子在 AI 能力钩子中最后运行，位于知识上下文注入之后：

```
GuardrailHook → PromptHook → TokenSavingPlanHook → MemoryHook → KnowledgeHook → WebSearchHook
```

## 搜索深度与域名过滤

两个设置塑造厂商侧搜索：

- **搜索深度（Search depth，**`low` / `medium` / `high`）—— 厂商每次查询收集多少搜索上下文。深度越高，回答依据越充分，单次查询成本也越高。
- **域名过滤（Domain filters）**—— 把搜索**限定**在指定域名内，或**排除**指定域名。各厂商对过滤的支持程度不同（有的只接受单一域名）；厂商不支持的过滤会被静默丢弃，不会报错。

你看到哪些字段取决于所选搜索引擎：字段按引擎自己声明的能力渲染，引擎无法兑现的设置不会出现。

## 激活

```python
response = client.chat.completions.create(
    model="openai/gpt-5.5",
    messages=[{"role": "user", "content": "这个月欧盟 AI 法案有什么变化？"}],
    extra_body={"web_search_id": "web-current-events"},
)
```

`web_search_id` 可在顶层或 `metadata` 内传入。该 ID 会在请求转发前被剥离。联网搜索工具也可以[通过策略绑定]({% link zh-CN/core-gateway/policies.md %})，从而在密钥或模型上自动激活——这是推荐的模式，调用方从此无需任何改动——请求中显式传入的 `web_search_id` 仍然优先。

{: .note }
**是否搜索、搜多广是组织层面的决定，而非调用方可以临时开启的开关。** 请求体里传入的 `web_search_options` 参数在所有请求上都会被无条件丢弃——无论是否绑定了工具——因为搜索按查询计费，所以它由这里的工具配置统一治理，与 Token 节省方案治理缓存是同一个道理。

在 **Playground** 中，可在请求设置里选择联网搜索工具，实测带搜索的回答。

## 创建联网搜索工具

打开 **AI Capabilities → Web Search**，选择 **Add Web Search**。表单包含：

- **Name（名称）** —— 在组织内唯一（字母、数字、`-`、`_`）。
- **Search mode（搜索模式）** —— 上述三种模式之一。表单还会显示你已部署的模型中有多少具备厂商内建搜索，让你知道回退模式实际会发生什么。
- **Engine（引擎）** —— 平台的搜索后端，从所在区域的引擎目录中选择（例如通用网页搜索，或仅查维基百科的百科引擎）。需要设置的引擎会显示额外字段。
- **Search depth（搜索深度）** 与 **Domain filters（域名过滤）** —— 仅当引擎支持时出现。
- **Description（描述）** —— 可选。
- **Test Engine（测试引擎）** —— 保存前对所选引擎执行一次真实查询，显示返回了多少条结果。

点击工具名称可查看其生效配置——模式、引擎、以及将作用于厂商侧搜索的设置。

**删除工具只会停止搜索，不影响其他功能。** 引用了它的策略照常工作——悬空的绑定是空操作，不是错误。删除对话框也会说明这一点。

## 区域可用性

在**中国区部署**中，不提供 Routero 搜索引擎；联网搜索只运行厂商侧路径（例如带内建搜索的 DashScope、Zhipu 模型家族）。当所在区域没有可用的网关引擎时，仪表板会显示警告，引擎选择器也只反映所在区域实际提供的引擎。

## 成本与可观测性

- **厂商侧搜索**由厂商按查询计费，费率取决于你配置的深度；费用出现在正常的用量视图中。
- **Routero 引擎**没有单次查询费用——其成本体现为注入结果块带来的额外提示词 token（上限五条结果）和少量额外延迟。
- 每个跳过了搜索的请求都会在请求元数据中记录原因（无查询词、无结果、模型不支持原生搜索、后端错误），让你能在日志中区分"搜了但没结果"和"根本没搜"。

---

## 组织隔离与权限

- **按组织作用域限定。** 联网搜索工具属于一个组织，仅对该组织可见。
- **谁能管理。** 组织管理员可创建、编辑和删除联网搜索工具。普通成员可查看。

---

## 与网关其余部分的组合

- **策略** —— 将联网搜索工具绑定到[策略]({% link zh-CN/core-gateway/policies.md %})，使其在密钥或模型上自动激活；调用方零改动。
- **知识库 / 记忆 / 提示词 / 护栏 / Token 节省** —— 其余 [AI 能力]({% link zh-CN/advanced-features.md %})按正常顺序作用于同一请求；护栏在任何搜索上下文加入之前检查调用方的原始输入，知识上下文则在搜索查询构造之前注入。
- **Playground** —— 在请求设置里选择联网搜索工具，实测带搜索的回答。

→ 关于将联网搜索绑定到密钥与模型，参见 [策略]({% link zh-CN/core-gateway/policies.md %})。
